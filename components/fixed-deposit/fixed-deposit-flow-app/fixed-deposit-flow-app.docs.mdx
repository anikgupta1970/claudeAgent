A React application that orchestrates the complete Fixed Deposit journey, including authentication (login + OTP), deposit configuration, bank details, preview, and submission. Uses dynamic UI rendering based on server configuration.

## Basic usage

```tsx
import { FixedDepositFlowApp } from '@api-banking/fixed-deposit.fixed-deposit-flow-app';

export function App() {
  return <FixedDepositFlowApp />;
}
```

## Journey flow

The application manages a multi-step flow:

1. **Login** - Collect credentials and accept terms
2. **OTP Verification** - Verify identity via OTP (inline modal)
3. **Deposit Details** - Configure FD type, amount, tenure, payout
4. **Bank Details** - Select funding source and branch
5. **Preview** - Review all entered information
6. **Submit** - Final submission with confirmation

## Architecture

### Dynamic UI Engine

The app uses a Dynamic UI Engine with a component registry to render steps based on server configuration:

```tsx
// Components are registered as factories
const registry = new UiComponentRegistry();
registry.register('LoginPage', loginPageFactory);
registry.register('DepositDetails', depositDetailsWrapperFactory);
registry.register('BankDetails', bankDetailsWrapperFactory);
registry.register('PreviewStep', previewStepFactory);
registry.register('SubmitStep', submitStepWrapperFactory);
```

### Journey Configuration

After successful authentication, the app fetches journey configuration from `/journey/config` which defines:
- Available steps and their order
- Component types and props for each step
- Layout configuration (stepper)

### Wrapper Components

Each step component is wrapped to handle API integration:

```tsx
// Example: DepositDetailsWrapper handles API submission
const DepositDetailsWrapper = ({ onContinue }) => {
  const { accessToken } = useJourneyContext();
  const { submit, isLoading, errors } = useJourneySubmission({
    endpoint: '/api/auth/deposit',
    method: 'PUT',
    requiresAuth: true,
  });

  return (
    <DepositDetails
      serverErrors={errors}
      isSubmitting={isLoading}
      onContinue={async (data) => {
        await submit(data, accessToken);
        onContinue?.();
      }}
    />
  );
};
```

## API Integration

The app communicates with the mock server at `API_BASE_URL` (default: `http://localhost:5000`):

| Step | Endpoint | Method |
|------|----------|--------|
| Fetch Terms | `/login/terms` | GET |
| Login | `/login/authorize` | POST |
| OTP Verify | `/login/token` | POST |
| Journey Config | `/journey/config` | GET |
| Deposit | `/api/auth/deposit` | PUT |
| Bank | `/api/auth/bank` | PUT |
| Submit | `/api/auth/submit` | POST |

## Environment variables

| Variable | Default | Description |
|----------|---------|-------------|
| `API_BASE_URL` | `http://localhost:5000` | Backend API URL |
| `CLIENT_ID` | `test-client-id` | Client identifier for API requests |

## Context providers

The app wraps content in `AuthenticationProvider` for state management:

```tsx
<AuthenticationProvider clientId={DEFAULT_CLIENT_ID}>
  <FixedDepositFlowAppContent />
</AuthenticationProvider>
```

## Stepper navigation

The journey uses a tab-style stepper component for navigation between steps. Steps are completed sequentially - users cannot skip ahead but can review completed steps.
