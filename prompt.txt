## Styling Rules

- Every component has its own `ComponentName.module.css` file (NOT .scss, NOT Tailwind, NOT inline styles)
- Use CSS custom properties for design tokens: var(--colors-primary-default), var(--spacing-medium), etc.
- Never hardcode colors or spacing values

## State Management

- JourneyContext.tsx uses useReducer — all journey state flows through dispatch()
- Steps read state via useJourney() hook and dispatch actions to advance
- Never use prop drilling for journey state

## API Client Rules

- All API calls MUST use the exported functions from src/api/client.ts
- Base URL: https://mahendra-shetake.mocks.apibanking.com (set via VITE_STITCH_API_BASE_URL env var)
- Never write raw fetch() calls in step components
- Never use mock/hardcoded data — always call the real API functions

## DebugPanel (REQUIRED in every app)

DebugPanel is a floating debug panel. It MUST be included. It provides:
- App Logs tab: intercepts console.log/warn/error with timestamps
- Network tab: intercepts window.fetch, logs request URL + body + response + timing
- App Data tab: shows live JourneyContext state as formatted JSON
- Pages tab: shows current step number and step completion progress

It is already wired into App.tsx. Output all files from flows/open-fd/components/DebugPanel/ exactly.
