# PART 1 — Stitch Backend Capabilities Reference

## Overview

Stitch is a banking middleware platform (Quarkus/OpenShift) that orchestrates customer origination, account opening, KYC, and payments via a form-based instruction model.

Core mental model: A Form contains Instructions (what to do: open account, create customer, etc.) and Sections (how to pay, who manages it, nominations, etc.). Both are polymorphic objects identified by discriminator fields (`instruction` and `section`).

Two APIs:
- Stitch API — runtime operations (forms, payments, customer management)
- Config Management API — admin configuration (products, branches, enums, originators, apps, terms, system settings)

## Authentication

All endpoints use Bearer JWT unless noted.

  Authorization: Bearer <token>

Token scopes:
- Standard bearer — most endpoints
- Admin bearer — POST /auth/token/claims, POST /individual-customers/find

Get token: POST /auth/token/claims

## Common Patterns

### Idempotency

POST /forms and POST /payments require an idempotency key:

  Idempotency-Key: <uuid-v4>

Repeating the same key with the same body returns the same response without re-processing. Different body with same key returns 422.

### Async Processing + Polling

POST /forms and POST /payments return 202 Accepted immediately. The application is processed asynchronously.

Poll for status:
- Simple status: POST /forms/status — returns overall application status
- Detailed status: POST /forms/detailed-status — returns per-instruction results

Poll until: status is COMPLETED, REJECTED, or FAILED (not PROGRESSING).

### Pagination (Config API)

All config list endpoints support query params page (default: 0) and size (default: 20).

### Draft-Aware Lifecycle

All config entities follow: DRAFT → PUBLISHED via promote.
1. POST /config/mgmt/fi/{resource} — creates in DRAFT
2. PUT /config/mgmt/fi/{resource}/{id}/promote — promotes to PUBLISHED

Only PUBLISHED entities are active in Stitch runtime operations.

## Error Format

All errors use RFC 7807 Problem Details (application/problem+json):

  {
    "status": 400,
    "title": "Bad Request",
    "instance": "/api/endpoint",
    "detail": "Human-readable explanation",
    "violations": [
      { "field": "fieldName", "in": "body", "message": "Constraint violation message" }
    ]
  }

When asked to build a banking onboarding app or any journey:

## Product: Open Fixed Deposit (Existing Customer)

When building for this product, say:

  "There is currently 1 flow available for an Open Fixed Deposit journey:

  1. Existing Customer — Customer is an existing bank account holder who wants to open a Fixed Deposit online. Authentication is mobile + OTP based. No KYC is required.

  Which flow would you like to build?"

### Journey — Flow 1

Steps: Login → Deposit Details → Bank Details → Preview → Submit FD

#### Step 1 — Login

Fields:
- Mobile number (pre-fill +91, customer enters 10 digits)
- Verify using — radio toggle: Date of Birth (default) or Pan Number
- Date of Birth — date picker (when DOB mode active)
- PAN Number — text input (when PAN mode active)
- Consent 1 + Consent 2 — both must be accepted to enable Continue

Consent 1: checkbox "I agree to the Terms & Conditions" → modal: "I authorize API Banking to access my account details and open a Fixed Deposit on my behalf."
Consent 2: checkbox "I agree to receive communications" → modal: "I consent to receive updates, alerts, and notifications related to my Fixed Deposit via SMS and email."

On Continue: open OTP modal (6 boxes, auto-advance, static hint "OTP has been sent to your registered mobile number", no timer/resend).
On OTP Submit: verify identity → navigate to Step 2.

Error states:
- Customer not found: "We could not find an account linked to this mobile number. Please check and try again."
- Invalid DOB/PAN: "The details entered do not match our records. Please try again."
- No linked SA: "No linked savings account found. Please contact your branch."
- Server error: "Something went wrong. Please try again in a moment."

#### Step 2 — Deposit Details

Product options load from bank config on mount. Show skeleton while loading.

Fields:
- Customer summary card (read-only) — name, DOB, PAN from Step 1
- FD Type — card radio: Withdrawable | Non-Withdrawable
- FD Amount — number input (min/max from config)
- Interest Payout — card radio: At Maturity | Monthly | Quarterly
- Maturity Instructions — dropdown (from config) + info banner below
- Tenure — 3 numeric inputs: Year / Month / Day
- Calculate FD Details button → reveals Maturity Details card (Rate of Interest, Interest Earned, Maturity Amount, Maturity Date)

Error states:
- Config load failure: "Unable to load product options. Please refresh." — disable Continue
- Amount out of range: "Amount must be between Rs.5,000 and Rs.1,00,00,000"
- Tenure out of range: "Tenure must be between 7 days and 10 years"
- Calculation failure: "Unable to calculate. Please check your inputs and try again."
- Invalid monthly/quarterly + renewal combination: "Renewal options are not available with monthly or quarterly interest payout"

#### Step 3 — Bank Details

Fields:
- FD Funding Amount — read-only from Step 2
- Fund via — card radio: Other Bank | HDFC Bank | Combined Funds
  - HDFC Bank shows masked linked SA + balance with green checkmark
  - Combined Funds shows info banner (not supported in demo)
- Branch search — opens Search Branch modal
- Add Nominee — checkbox; opens Add Nominee modal when checked

Search Branch Modal: toggle location-based vs PIN code. Location: State dropdown → City dropdown (filtered by state) → Branch dropdown. Branch result shows name, address, IFSC.

Add Nominee Modal: Relationship (dropdown), Name, DOB. Guardian section auto-reveals if nominee is minor (age < 18): guardian name, relationship, DOB.

Funding flow: HDFC Bank = direct form submit. Other Bank = payment gateway redirect, submit after confirmed return.

Error states:
- Branch list fails: "Unable to load branch list. Please try again."
- No branch selected: "Please select a branch before continuing."
- Nominee relationship fails: "Unable to load relationship options. Please try again."

#### Step 4 — Preview

Read-only review. Back returns to Step 3 with all state preserved.

Sections:
- Customer Details: Name, DOB, PAN
- FD Details: FD Type, Amount, Tenure, Interest Payout, Maturity Instruction, Rate of Interest, Interest Earned, Maturity Amount, Maturity Date
- Bank Account Details: Linked account (masked), Branch, IFSC
- Nominee Details: Relationship, Name, DOB (shown only if nominee added)

On Confirm: disable button immediately, show spinner overlay "Submitting your application..."
- HDFC Bank: submit directly → Step 5
- Other Bank: redirect to payment gateway → on return show "Waiting for payment confirmation..." → submit → Step 5

Error states:
- Validation failure: "Unable to submit. Please check your details."
- Server failure: "Submission failed due to a server error. Please try again."
- Payment gateway failure: "Payment was not completed. Please try again." — stay on Step 4
- Payment confirmation failure: "Payment could not be confirmed. Please try again."

#### Step 5 — Submit FD (Success)

Show spinner "Processing your application..."

Poll until COMPLETED, REJECTED, or FAILED (stop after ~20 seconds).

COMPLETED: Green checkmark + summary card (reference number, masked FD account number, all FD details, nominee if added).

Still PROGRESSING after 20s: "Your application has been submitted and is being processed. Reference ID: [XXXXXX]. You will receive a confirmation shortly."

REJECTED / FAILED: "Your application could not be processed. Please contact support."

Always show reference ID. Always show Back to Home button that resets the journey.

## Adding New Flows or Products

New flow under existing product: Add a Flow N section, state when to use it, define only steps that differ from the shared journey.

New product: Add a Product section with its own prompt, shared journey steps, and flows.
